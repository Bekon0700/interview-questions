Category-level retrieval prompts for `/review`, comparing Topics in this Category. Pulled from [[comparison]].

> [!question] A company needs CI/CD in a fully air-gapped, on-prem environment with no internet access to any vendor's cloud. Which tool fits naturally, and why do the other two struggle with it?
> —

> [!question] A team wants reviewers to click through a live, disposable environment for every merge request without building that infrastructure themselves. Which tool gives this natively, and what would the other two require you to build by hand?
> —

> [!question] Contrast how GitHub Actions, Jenkins, and GitLab CI each handle "run this pipeline logic in more than one repo without copy-pasting it."
> —

> [!question] Explain the difference between GitHub Actions' default parallel-jobs-with-`needs:` execution model and GitLab CI's default sequential-stages-with-parallel-jobs-within-a-stage model.
> —

> [!question] Why does self-hosting Jenkins carry meaningfully more operational burden than using GitHub Actions or GitLab CI on their hosted (SaaS) offerings?
> —

> [!question] A team is already fully on GitLab, including its Container Registry. What concrete integration friction would they take on by switching their pipelines to Jenkins instead?
> —

> [!question] Explain to a beginner, in plain terms, why "which CI/CD tool should we use" often comes down to "where does your code already live" rather than a feature-by-feature bake-off.
